# 테스트 모드 개발 진행 사항

테스트 모드 기능의 구현 현황과 단계별 남은 작업을 정리한 문서입니다.  
설계 기준: **`docs/테스트_모드_설계.md`**

본 문서의 최우선 원칙:

- 테스트 모드는 **로컬 테스트 전용 기능**이다.
- 테스트 모드로 인해 **운영 로직/운영 데이터/운영 화면 동작이 바뀌면 안 된다**.
- 테스트 모드 OFF 시 실행 경로는 기존과 **완전히 동일**해야 한다.

**진행 범위**: 이 문서의 "다음 진행 사항"은 **테스트 모드 관련 개발만** 대상으로 한다. 코드 서명·SmartScreen·정식 배포 등은 해당 앱 개발이 완전히 끝나고 정식 등록 후 배포할지 결정할 예정이다.

## 목적/진행 프로세스 (자연어)

이 개발 진행 사항의 목적은 운영 기능을 바꾸는 것이 아니라, 개발/QA가 로컬 환경에서 다양한 상황을 빠르게 재현해 검증할 수 있게 하는 데 있다.  
즉, 서버 시간이 맞지 않거나 특정 정책 응답을 받기 어려운 상황에서도, 테스트 모드에서 값만 바꿔 시업/종업/이석/임시연장/긴급사용/긴급해제 흐름을 반복 검증할 수 있어야 한다.

진행 프로세스는 다음과 같다.

1. 운영 로직과 테스트 로직을 먼저 분리한다. (테스트 모드 OFF 시 기존 코드와 동일 동작 보장)
2. 테스트 모드 상태를 `test-mode-state.json`에만 저장해 운영 상태 파일과 완전히 분리한다.
3. 화면 타입/동작 모드 강제값을 적용해 핵심 시나리오를 즉시 재현 가능하게 만든다.
4. Drawer에서 서버 응답값을 임의로 입력·적용하고, 프리셋으로 반복 테스트를 단순화한다.
5. `WorkTimeResponse` 전 필드 커버리지를 문서로 추적해 “테스트 가능한 값”의 누락을 지속적으로 제거한다.
6. 마지막으로 운영 차단 장치(`allowTestMode`, 환경 조건)를 적용해 실운영 노출 위험을 막는다.

## 테스트 모드 ON 시 무엇이 달라지는가

테스트 모드를 **ON**으로 두면 아래만 바뀌고, 나머지(로그인·API 스펙·잠금 정책 로직)는 그대로다.

| 구분 | 테스트 모드 OFF (운영) | 테스트 모드 ON |
|------|-------------------------|----------------|
| **근태 데이터** | 서버 `getPcOffWorkTime` 호출 결과 사용 | **API 호출 없음**. `lastWorkTimeData`(또는 mock) + **overrides** 병합, **forceScreenType** 적용한 값만 사용 |
| **잠금 여부** | 서버 근태·시간·이석 감지로 판단 | 위 테스트용 데이터만 보고, **screenType이 before/off/empty이면 잠금**으로 판단 |
| **잠금화면 내용** | 서버에서 내려준 근태·화면 타입으로 표시 | 테스트용 데이터(시업/종업/이석)로 표시 |
| **동작 모드 배지** | 실제 모드(NORMAL/TEMP_EXTEND/긴급사용/긴급해제) | **forceOperationMode**가 AUTO가 아니면 그 값으로 표시 |
| **설정 저장** | 운영용 state.json 등만 사용 | **test-mode-state.json**에만 저장·복원 (운영 파일과 분리) |

정리하면, **테스트 모드 ON = “근태/잠금/모드 표시를 전부 로컬 설정값으로 덮어써서 시업·종업·이석·임시연장·긴급사용 등을 재현”**한다. OFF로 돌리면 위 경로는 모두 끄고, 다시 서버·운영 로직만 사용한다.

## 4. 데이터 모델 (설계서 §6 기준)

저장 대상 예시 (`test-mode-state.json` 고정):

```json
{
  "testMode": {
    "enabled": false,
    "bypassApi": true,
    "forceScreenType": "AUTO",
    "forceOperationMode": "AUTO",
    "overrides": {
      "pcOnYmdTime": "202602270830",
      "pcOffYmdTime": "202602271830",
      "pcExCount": 0,
      "pcExMaxCount": 3,
      "pcExTime": 30,
      "leaveSeatUseYn": "Y",
      "leaveSeatTime": 10,
      "leaveSeatReasonYn": "YES",
      "leaveSeatReasonManYn": "YES",
      "leaveSeatUnlockRequirePassword": true
    }
  }
}
```

- **1단계**: `enabled`, `forceScreenType`, `forceOperationMode`, (선택) `overrides` 저장/복원.
- **2단계**: `bypassApi`, 전체 overrides 키 확장.
- **3단계**: 잠금화면 문구/리소스 override 키 추가 시 스키마 확장.

주의:

- 운영 파일(`state.json`, `config.json`의 로그인/운영 필드)과 교차 저장 금지.
- 테스트 모드 OFF 시에도 마지막 테스트 세트는 `test-mode-state.json`에만 유지(빠른 재시험용), 운영 로직에는 미반영.

- `app/core/api-client.ts`의 `WorkTimeResponse` 전 필드

## 5. 프리셋 버튼 검증 체크리스트

테스트 모드 ON 후 Drawer에서 각 프리셋 클릭 시 **잠금 프리셋(before/off/empty_*)은 잠금화면이 즉시 열림**.

| 프리셋 | 기대 동작 | 확인 |
|--------|-----------|------|
| 시업 잠금 재현 | forceScreenType=BEFORE, 잠금화면(시업 전) 표시 | ⬜ |
| 종업 잠금 재현 | forceScreenType=OFF, 잠금화면(종업) 표시 | ⬜ |
| 이석 잠금 (사유필수) | forceScreenType=EMPTY, leaveSeatReasonYn/ManYn=YES → PC-ON 시 **사유 입력 필수** (lock.js calcLeaveSeatPolicy) | ⬜ |
| 이석 잠금 (사유면제) | forceScreenType=EMPTY, leaveSeatReasonYn/ManYn=NO → 사유 입력 **면제** | ⬜ |
| 모드: 일반 / 임시연장 / 긴급사용 / 긴급해제 | forceOperationMode 반영, 작동정보 배지·버튼 가시성 변경 | ⬜ |
| 초기화 | forceScreenType=AUTO, forceOperationMode=AUTO, overrides={} | ⬜ |

**이석 관련**: 프리셋의 `leaveSeatReasonYn`/`leaveSeatReasonManYn` 값은 **lock.js `calcLeaveSeatPolicy()`** 및 **app/core/leave-seat.ts**의 `requireReason` 판별과 동일 기준(둘 다 YES → 사유 필수). getLockInitialWorkPayload → getTestModeWorkData()로 잠금창에 전달되므로 최신 이석 소스와 동일하게 테스트됨.

## 6. 리스크 및 대응 (설계서 §12)

| 리스크 | 대응 |
|--------|------|
| 테스트 모드 코드가 운영 경로 오염 | `if (!testModeEnabled) return ...` 조기 분기 유지, 테스트 전용 변수·분기만 사용 |
| 테스트 모드가 운영 잠금 판단을 부분적으로만 덮어써 동작 불일치 발생 | `getWorkTime`, `isLockRequired`, 잠금창 초기 데이터, 주기 체크 경로를 동일 규칙으로 통합 적용 |
| 테스트 모드에서 동작 모드 강제가 일부 경로에만 반영되어 버튼/상태 표기가 어긋남 | `getOperationMode`, mode-changed 이벤트, UI 배지/버튼 가시성 판단 경로를 동일 강제 규칙으로 통합 |
| 잘못된 입력으로 UI 깨짐 | Drawer 입력 검증(시간 12자리, 숫자 범위), 유효성 실패 시 적용 차단 |
| QA가 테스트 모드 상태를 잊고 운영 테스트 수행 | 상단 고정 배너, 트레이 상태 표시, 테스트 모드 관련 로그 기록 |
| 운영 배포에서 테스트 모드 노출 | `allowTestMode=false` 기본값 + 빌드 타입/환경 플래그로 접근 차단 |
