# 5240 PcOff Agent — 테스트 모드 매뉴얼

## 소스 점검 결과 요약 (로직 검토)

전체 테스트 모드 관련 소스(Main / Preload / Renderer)를 점검한 결과, **의도된 대로 동작하며 로직상 문제는 없습니다.**

| 구분 | 점검 내용 | 결과 |
|------|-----------|------|
| **테스트 모드 분리** | testModeEnabled=false 시 getWorkTime·isLockRequired·getLockInitialWorkPayload 등이 모두 기존 API/캐시 경로만 사용 | ✅ |
| **override 병합** | mergeTestOverrides가 base에 testModeOverrides만 반영, undefined/null/"" 제외 | ✅ |
| **getTestModeWorkData** | base(lastWorkTimeData 또는 mock) → overrides 병합 → forceScreenType 적용 → 로컬 이석 반영 순서 고정 | ✅ |
| **잠금 해제 시 초기화** | showTrayInfoInCurrentWindow에서 testModeEnabled&&lock 시 테스트 모드 OFF·설정 초기화·저장·브로드캐스트로 재잠금 무한루프 방지 | ✅ |
| **allowTestMode** | config.allowTestMode===false 시 핫키·setTestModeEnabled(true)·setTestModeState({enabled:true}) 무시, getTestModeState.allowed 반영 | ✅ |
| **Drawer 동기화** | 프리셋 클릭 시 patchOnly:true로 프리셋에 있는 키만 갱신, 잠금화면 문구·리소스 등 기존 값 유지 | ✅ |
| **값 적용/시작** | collectOverridesFromDrawer로 시간·근태·잠금화면 12개 필드 수집, 유효성(시업/종업 12자리) 검사 후 setTestModeState 호출 | ✅ |
| **잠금화면 override** | overrides의 lockScreen* 필드가 getTestModeWorkData → getLockInitialWorkPayload → 잠금창에 전달, lock.js에서 그대로 사용 | ✅ |

**참고**: 잠금화면 문구·리소스 필드를 **비우고 [값 적용]**만 누르면, 해당 키는 overrides에 포함되지 않아 **이전에 넣었던 값이 유지**됩니다. 개별 항목을 “지우고” 적용하려면 **초기화** 프리셋 선택 후 **[시작]**을 눌러 overrides를 비운 뒤 사용하세요.

## 1. 테스트 모드 개요

- **목적**: 개발/QA가 서버 API나 실제 시간에 의존하지 않고, **시업 전·종업·이석·임시연장·긴급사용·긴급해제** 등을 로컬에서 바로 재현하기 위함.
- **특징**  
  - 테스트 모드 ON 시 **getPcOffWorkTime 등 API 호출 없이** 로컬 설정값만 사용.  
  - **트레이 메뉴에는 테스트 모드 항목이 없음.** 진입/해제는 **핫키 전용**.

---

## 2. 테스트 모드 켜기/끄기

| 동작 | 방법 |
|------|------|
| **켜기** | **Ctrl+Shift+T** (Windows) / **Cmd+Shift+T** (macOS) |
| **끄기** | 동일 키 한 번 더 입력 |

- 켜지면 **작동정보 화면 상단**에  
  **「테스트 모드 ON (Ctrl+Shift+T로 해제)」** 가 표시됩니다.
- **테스트 모드 ON 시** 강제 화면 타입은 **AUTO**로 초기화되고, **「잠금 의도」가 없는 상태**로 둡니다. 따라서 저장된 overrides나 서버 캐시가 종업(off)으로 계산되더라도, **[시작]을 누르기 전에는 주기 잠금 검사로 잠금창이 뜨지 않습니다.** 프리셋(시업 전/종업/이석) 선택 후 **[시작]**을 눌렀을 때만 해당 잠금화면이 열리고, 그때부터 주기 검사에서도 잠금이 유지됩니다.
- **config.json**에 `"allowTestMode": false` 이면 테스트 모드는 켜지지 않습니다(핫키·UI 모두 무시).

## 3. 설정 패널(Drawer) 사용법

테스트 모드가 **ON**일 때만 **우측 Drawer(테스트 모드 설정)** 가 보입니다.

### 3.1 화면 타입·동작 모드

- **강제 화면 타입**: AUTO / 시업 전(BEFORE) / 종업(OFF) / 이석(EMPTY) 중 선택.  
  BEFORE·OFF·EMPTY 선택 후 **[시작]** 시 해당 잠금화면이 열립니다.
- **강제 동작 모드**: AUTO / 일반 / 임시연장 / 긴급사용 / 긴급해제 중 선택.  
  작동정보 배지·잠금화면 버튼 노출 등이 이 모드에 맞게 동작합니다.

### 3.2 시간·근태 값 입력

- **기준 시각 (exCountRenewal)**: `YYYYMMDDHHmm` 12자리. **강제 화면이 AUTO일 때만** 사용됩니다. 현재 PC 시각이 이 시각 **이전**이면 종업(off), **이후**면 시업 전(before)으로 판단합니다. 비우면 서버/모킹 값 사용.
- **시업 시간 / 종업 시간**: `YYYYMMDDHHmm` 12자리. 잠금화면 문구·표시용.

**어떤 시간값을 기준으로 동작하나요?**

| 상황 | 기준 |
|------|------|
| **강제 화면 타입**을 시업 전/종업/이석 중 하나로 선택한 경우 | **시간값과 무관**하게 선택한 화면 타입으로만 동작합니다. 시업/종업 시간 입력값은 잠금화면 **문구·표시용**입니다. |
| **강제 화면 타입 = AUTO**인 경우 | **현재 PC 시각(now)** 과 서버/오버라이드의 **exCountRenewal**(임시연장 차수 초기화 기준 시각)으로 시업 전/종업을 구분합니다. `현재 시각 < exCountRenewal` → 종업(off), `현재 시각 ≥ exCountRenewal` → 시업 전(before). Drawer의 시업/종업 시간은 잠금화면 표시·데이터 규격용이며, 실제 before/off 판정은 **exCountRenewal** 기준입니다. |
- **임시연장**: 사용 횟수, 최대 횟수, 1회 분.
- **이석**: 사용(Y/N), 임계 시간(분), 사유 여부·사유 필수(YES/NO).
- **긴급사용 허용**: YES/NO.

입력 후 **[값 적용]**을 누르면 현재 입력값이 overrides에 반영됩니다.  
**[시작]**을 누르면 **화면 타입·동작 모드 + 위 값**을 한 번에 적용하고, 잠금 타입이면 잠금화면을 엽니다.

### 3.3 잠금화면 문구·리소스 (선택)

- **시업 전 / 종업 / 이석** 각각  
  **제목, 안내 문구, 배경 URL, 로고 URL** 4칸씩 입력할 수 있습니다.
- 비워 두면 서버·config 값이 그대로 사용됩니다.
- **프리셋을 눌러도 이 칸들은 바뀌지 않고 유지**됩니다(프리셋은 화면 타입·모드·일부 근태 값만 채움).
- **한 항목만 “지우고” 적용**하는 것은 지원하지 않습니다.  
  전부 비우려면 **초기화** 프리셋 선택 후 **[시작]**으로 overrides를 비운 뒤 사용하세요.

### 3.4 프리셋

- 프리셋을 누르면 **폼만 채워지고**, 적용·잠금창 오픈은 되지 않습니다.
- **적용·잠금화면 열기**를 하려면 반드시 **[시작]**을 눌러야 합니다.

| 프리셋 | 동작 |
|--------|------|
| 시업 잠금 재현 | 강제 화면 = 시업 전 |
| 종업 잠금 재현 | 강제 화면 = 종업 |
| 이석(사유 필수) | 강제 화면 = 이석, 이석 사유 필수 |
| 이석(사유 면제) | 강제 화면 = 이석, 이석 사유 면제 |
| 모드: 일반/임시연장/긴급사용/긴급해제 | 강제 동작 모드만 변경 |
| 초기화 | 화면 타입·동작 모드·overrides 전부 초기화 |

**모드 프리셋 후 [시작]을 누르면 어떻게 되나요?**

- **모드만** 선택(일반/임시연장/긴급사용/긴급해제)한 상태에서 [시작]을 누르면 **강제 화면 타입은 AUTO**로 유지됩니다.
- 동작: **선택한 동작 모드**와 Drawer에 입력한 **overrides**만 적용되고, **잠금창은 열리지 않습니다.** 작동정보 화면이 갱신되며 상단 배지가 해당 모드(일반/임시연장/긴급사용/긴급해제)로 바뀝니다. 주기 잠금 검사에서도 잠금이 걸리지 않습니다.
- 잠금화면을 띄우려면 **시업 전/종업/이석** 중 하나를 선택한 뒤 [시작]을 눌러야 합니다.

## 4. 버튼 정리

| 버튼 | 동작 |
|------|------|
| **값 적용** | Drawer에 입력한 **시간·근태·잠금화면 문구·리소스**를 overrides에 반영. 잠금창은 열지 않음. |
| **시작** | **화면 타입 + 동작 모드 + 위 overrides**를 한 번에 적용.  
  강제 화면이 시업 전/종업/이석이면 **잠금화면을 연다**. |

## 5. 주의사항

1. **테스트 모드 ON 문구**  
   상단에 「테스트 모드 ON」이 보이면 테스트용 설정이 적용된 상태이므로, 실제 업무용이 아님을 인지하고 사용하세요.

2. **잠금 해제 시 테스트 모드 자동 OFF**  
   테스트 모드로 연 잠금화면에서 **PC-ON 등으로 잠금 해제**를 하면 **테스트 모드가 자동으로 OFF**됩니다.  
   다시 테스트하려면 **Ctrl+Shift+T** / **Cmd+Shift+T**로 다시 켜면 됩니다.

3. **앱 시작 시**  
   앱을 새로 실행하면 **항상 테스트 모드는 OFF**로 시작합니다.

4. **운영 배포**  
   `config.json`에서 `allowTestMode: false`로 두면 테스트 모드(핫키 포함)가 비활성화됩니다.

## 6. 트러블슈팅

| 현상 | 확인 사항 |
|------|-----------|
| 핫키로 테스트 모드가 켜지지 않음 | `config.json`에 `allowTestMode: false` 인지 확인. macOS는 **손쉬운 사용**에서 해당 단축키 허용 여부 확인. |
| Drawer가 안 보임 | 테스트 모드가 ON인지 확인(상단 문구). ON인데도 안 보이면 창을 한 번 닫았다가 트레이 등으로 다시 열어보기. |
| 프리셋 선택 시 잠금화면 문구가 비어 보임 | 프리셋은 **해당 프리셋에 있는 필드만** 폼에 반영합니다. 잠금화면 문구·리소스 입력란은 그대로 유지되는 것이 정상입니다. |
| 잠금화면 문구를 “지우고” 적용하고 싶음 | 입력란을 비우고 [값 적용]만 하면 **이전 값이 유지**됩니다. **초기화** 프리셋 선택 후 **[시작]**으로 전체 overrides를 비운 뒤, 필요한 값만 다시 넣어 사용하세요. |
