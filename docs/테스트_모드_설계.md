## 1. 배경 및 목표

현재 시업(before), 종업(off), 이석(empty) 화면/행동은 서버 응답과 실제 시간 흐름에 크게 의존한다.  
테스트 효율을 위해, 에이전트 내부에서 **테스트 모드**를 켜고 로컬 값만으로 화면/동작을 재현할 수 있어야 한다.

목표:

1. 테스트 모드 ON/OFF 기능 제공
2. 테스트 가능한 값 대부분을 로컬에서 설정
3. 에이전트 화면 내 동작(버튼) + 핫키로 테스트 모드 진입
4. 테스트 모드 전용 설정 패널(UI) 제공
5. 설정값으로 시업/종업/이석 상태를 즉시 재현

---

## 2. 범위

### 2.1 In Scope

- 테스트 모드 상태 관리(ON/OFF)
- 핫키 및 UI 진입점
- 테스트 모드 설정 패널(우측 Drawer)
- 로컬 설정값 저장/복원
- 시업/종업/이석 상태 강제 재현
- 테스트 모드 활성 시 API 우회 동작(선택적)

### 2.2 Out of Scope

- 운영 사용자에게 노출되는 정책 변경
- 서버 API 스펙 변경
- 기존 잠금 정책 자체 로직 변경(운영 모드 기준)

---

## 3. 요구사항 정리 (사용자 요청 매핑)

| 요청 | 설계 반영 |
|---|---|
| 1. 테스트 모드 필요 | `testMode.enabled` 도입 |
| 2. 설정 가능한 모든 값을 로컬에서 설정 | `testMode.overrides` + 시나리오 프리셋 |
| 3. 에이전트 화면에서 핫키/동작으로 활성 | 메뉴 버튼 + 전역 핫키(`Ctrl/Cmd+Shift+T`) |
| 4. 테스트 모드시 우측이든 어디에서 값 설정 | 우측 Drawer(`Test Mode Panel`) |
| 5. 설정된 값으로 시업/종업/이석 재현 | `screenType` 강제값(`before/off/empty`) + 시간값/정책값 즉시 반영 |

## 4. 동작 설계

### 4.1 진입/해제

- 핫키:
  - Windows: `Ctrl+Shift+T`
  - macOS: `Cmd+Shift+T`
- UI:
  - 에이전트 화면 상단 우측에 `테스트 모드` 토글 버튼
  - ON 시 우측 Drawer 자동 오픈
  - OFF 시 Drawer 닫힘 + override 비활성(값은 유지 가능)

### 4.2 모드 우선순위

1. `testMode.enabled === true` + `testMode.forceScreenType` 지정 시, 화면 타입 강제
2. 강제값 없으면 override된 시간/정책값으로 기존 `resolveScreenType` 계산
3. 테스트 모드 OFF 시 기존 운영 로직 100% 복귀

### 4.3 재현 대상

- 시업 상태: `screenType=before` 강제 또는 `now < pcOnYmdTime`
- 종업 상태: `screenType=off` 강제 또는 `now >= pcOffYmdTime`
- 이석 상태: `screenType=empty` 강제 또는 `isLeaveSeat=true` 강제

## 5. UI 설계 (Test Mode Drawer)

우측 Drawer 섹션:

1. 기본
- 테스트 모드 ON/OFF
- API 우회(로컬 강제) ON/OFF
- 강제 화면 타입: `AUTO | BEFORE | OFF | EMPTY`

2. 시간/근태
- `pcOnYmdTime`
- `pcOffYmdTime`
- `pcExCount`, `pcExMaxCount`, `pcExTime`
- `exCountRenewal`

3. 정책
- `pcoffEmergencyYesNo`
- `leaveSeatUseYn`, `leaveSeatTime`, `leaveSeatReasonYn`, `leaveSeatReasonManYn`
- `leaveSeatUnlockRequirePassword`

4. 잠금 화면 문구/리소스
- before/off/leave 별 title, message
- backgroundUrl, logoUrl

5. 시나리오 프리셋
- `시업 잠금 재현`
- `종업 잠금 재현`
- `이석 잠금 재현(사유필수)`
- `이석 잠금 재현(사유면제)`
- `초기화`

## 7. 구현 포인트

### 7.1 Main Process (`app/main/index.ts`)

- 전역 상태 추가: `testModeState`
- 핫키 등록 추가: `Ctrl/Cmd+Shift+T`
- `getWorkTime`, `isLockRequired`, `applyResolvedScreenType` 경로에 테스트 override 병합
- IPC 추가:
  - `pcoff:getTestModeState`
  - `pcoff:setTestModeState`
  - `pcoff:applyTestPreset`

### 7.2 Preload (`app/preload/index.ts`)

- Renderer 노출 API:
  - `getTestModeState()`
  - `setTestModeState(patch)`
  - `applyTestPreset(name)`
  - `onTestModeChanged(handler)`

### 7.3 Renderer (`app/renderer/main*.js/html`)

- 상단 버튼 + 우측 Drawer UI
- 각 입력값 검증(시간 12자리 포맷, 숫자 범위)
- 적용 즉시 미리보기(잠금 상태/버튼 가시성/문구 반영)

---

## 8. 로그/가시성

테스트 모드 관련 이벤트 로깅:

- `TEST_MODE_ENABLED`
- `TEST_MODE_DISABLED`
- `TEST_MODE_OVERRIDE_UPDATED`
- `TEST_MODE_PRESET_APPLIED`
- `TEST_MODE_FORCE_SCREEN_CHANGED`

로그에는 사용자 식별값을 넣지 않고 설정 키/값 변화만 기록.

---

## 9. 안정성/보안

- 기본값 OFF
- 운영 배포에서도 접근 가능하되, 트레이 메뉴의 `개발/테스트` 섹션에서만 노출
- 필요 시 `config.json`의 `allowTestMode` 플래그로 완전 비활성 가능
- 테스트 모드 ON 배너(시각적 경고) 상시 표시

---

## 10. 수용 기준 (Acceptance Criteria)

1. 핫키 또는 UI 버튼으로 테스트 모드 ON/OFF 가능
2. 우측 Drawer에서 주요 값 수정 후 즉시 반영
3. 프리셋 1회 클릭으로 시업/종업/이석 화면 각각 재현
4. 앱 재시작 후 테스트 모드 설정 복원
5. 테스트 모드 OFF 시 운영 로직과 결과 동일

---

## 11. 단계별 구현 제안

1단계:
- 상태 저장/핫키/ON-OFF 토글
- forceScreenType(`before/off/empty`)만 우선 적용

2단계:
- Drawer UI + 주요 시간/정책 override 입력
- 프리셋 적용/초기화

3단계:
- 잠금화면 문구/이미지 override
- 로그 고도화 + 비개발자 테스트 가이드 문서 업데이트

---

## 12. 리스크 및 대응

- 리스크: 테스트 모드 코드가 운영 경로를 오염
  - 대응: `if (!testMode.enabled) return originalPath` 형태로 조기 분기
- 리스크: 잘못된 입력으로 UI 깨짐
  - 대응: 입력 검증 + 유효성 실패 시 적용 차단
- 리스크: QA가 테스트 모드 상태를 잊고 운영 테스트 수행
  - 대응: 상단 고정 배너 + 트레이 상태 표시 + 로그 기록
