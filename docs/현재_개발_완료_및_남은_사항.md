# 현재 개발 완료 및 남은 사항

5240 PcOff Electron 에이전트의 **현재까지 개발된 기능**과 **남은 개발·점검 사항**을 한 문서로 정리합니다.

- **작성일**: 2026-02-27
- **상세 참고**: `docs/다음_개발_진행_사항.md`, `docs/테스트_모드_개발_진행_사항.md`, `docs/팀_공유_완료현황_및_남은일.md`

## 1. 현재까지 개발된 것 (운영 기능)

에이전트(프론트) 단독으로 구현·검증을 마친 항목입니다. 서버 API가 있으면 연동 완료, 없으면 호출부·Fallback·검증 스크립트까지 준비된 상태입니다.

### 1.1 로그인·로그아웃

| 항목 | 내용 |
|------|------|
| 로그인 2단계 | 전화번호 → 서비스영역 조회(getPcOffServareaInfo) → 선택·ID·비밀번호 → getPcOffLoginUserInfo |
| 저장 | state.json (userServareaId, userStaffId, loginUserId, loginUserNm, posNm, corpNm, lastLoginAt) |
| 로그아웃 | 전역 핫키(Cmd/Ctrl+Shift+L), clearLoginState, state.json·config.json 로그인 정보 제거 |
| 로그인 직후 | invalidateRuntimeConfigCache, fetchWorkTimeWithLockScreen 1회 조회 → 근태·이석·긴급해제 등 전체 설정 반영, leaveSeatDetector 시작 |

### 1.2 메인(잠금) 화면·API 연동

| 항목 | 내용 |
|------|------|
| 근태 조회 | getPcOffWorkTime, getLockPolicy 병합, fetchWorkTimeWithLockScreen(문구·잠금화면 정책 포함) |
| 버튼 4종 | 임시연장(callPcOffTempDelay), 긴급사용(callPcOffEmergencyUse), PC-ON(callCmmPcOnOffLogPrc IN), PC-OFF(OUT) |
| 긴급사용 OTP 흐름 | 버튼 클릭 → 옵션(본인/조직장)에 따른 안내 메시지 표시 → 확인 시에만 Step1(OTP 발송) → 입력 화면. 취소 시 OTP 미발송. OTP 수신자: **서버** getPcOffWorkTime / lock-policy / getLockScreenInfo 중 한 경로에서 내려주면 적용, 없을 때만 config fallback. `docs/서버_긴급사용_OTP_수신자_연동.md` 참고. |
| 시업/종업 로직 (FR-13) | resolveScreenType(exCountRenewal), screenType before/off/empty, applyResolvedScreenType |
| 임시연장 | 횟수 소진 시 버튼 숨김, preserveLocalPcExCountIfHigher 전 경로 적용, state.json tempExtendUntil·lastWorkTimeSnapshot 복원 |
| API 6종 | getPcOffWorkTime, getPcOffServareaInfo, getPcOffLoginUserInfo, callPcOffTempDelay, callPcOffEmergencyUse, callCmmPcOnOffLogPrc — Main IPC·Preload·Renderer 연동, API v1.9 필드 반영 |

### 1.3 이석·긴급해제·고객사 설정

| 항목 | 내용 |
|------|------|
| 이석 감지 | LeaveSeatDetector(Idle 5초 폴링·Suspend/Resume), leaveSeatUseYn·leaveSeatTime 정책 갱신 |
| 이석 체크 적용 | 일반(NORMAL)·임시연장·긴급사용에서 적용. 긴급해제(EMERGENCY_RELEASE)에서만 제외. isAlreadyLockedByWorkHours는 pcOn/pcOff 기준 |
| 이석 잠금화면 | screenType=empty, config.lockScreen.leave 문구·배경·로고, 주/보조 동일 데이터·did-finish-load 전송 |
| 이석 해제 | PC-ON 클릭 시 leaveSeatUnlockRequirePassword면 비밀번호 모달, verifyLeaveSeatUnlock(PHP·.do)·로컬·mock 우선순위 |
| 긴급해제 | EmergencyUnlockManager(5회 차단·3시간 만료), PHP(sendLockPass.php) 우선, 404 시 안내 문구 |
| 고객사 설정 (FR-14) | getLockPolicy, 30분 캐시·폴링, lockScreen.screens·unlockPolicy·leaveSeatUnlockRequirePassword 병합 |

### 1.4 다중 디스플레이·창 관리

| 항목 | 내용 |
|------|------|
| 다중 디스플레이 | 주 디스플레이(mainWindow) + 보조당 잠금창(lockWindowsByDisplayId), display-added/removed 핫플러그 |
| 보조 창 | ensureLockWindowsForAllDisplays, await + 500ms 재시도, broadcastWorkTimeToLockWindows |
| 잠금 시 | 닫기 차단, 강제 전체 화면, blur 시 재진입, closeAllLockWindows(해제/로그인 시) |
| 해제 시 디폴트 크기 | **모든** 잠금 해제·작동정보 전환 경로에서 620×840(로그인 520×620) 보장. showTrayInfoInCurrentWindow·createTrayInfoWindow·createLoginWindow에서 표시 직전 setFullScreen(false) 및 setSize 호출(Windows 풀스크린 유지 이슈 방지). 경로: 임시연장·긴급사용·긴급해제·PC-ON·트레이 클릭·핫키(Cmd+Shift+I)·Dock activate·앱 재실행 후 잠금 미표시 시. |

### 1.5 기타 운영 기능

| 항목 | 내용 |
|------|------|
| 자동 업데이트 | electron-updater, 무확인 다운로드, 재시도 큐, 실패 구분 로깅(UPDATE_SIGNATURE_INVALID 등) |
| 비밀번호 변경 확인 | pwdChgYn=Y 감지, 확인-only 모달·IPC |
| Agent Guard | 무결성 체크·파일 모니터링·자동 복구 트리거·탐지 로그 |
| Ops Observer | heartbeat·로그 배치 전송·크래시 감지·오프라인 보고 |
| 오프라인 복구·잠금 | OfflineManager(30분 유예·잠금), 연속 성공 2회 복구, 잠금 화면 UI |
| 설치자·격리 | installer-registry.json, 설치/삭제 탐지, 격리 모드(isolation-mode.json) |
| 트레이·작동정보 | getTrayOperationInfo·refreshMyAttendance, 단일 창 전환(main/lock/login) |
| 이석정보 서버 전송 | LeaveSeatReporter(START/END), reportLeaveSeatEvent.do, 재시도 큐 |
| CI·릴리스 | GitHub Actions Windows/Mac 빌드·Release 업로드 |
| 시뮬레이터 | Flow-01~08, leave_seat_unlock 등 11개 시나리오, run-all 통과 |
| 연동 준비 | run-integration-check-1-2-3.mjs, check-lock-screen-config.mjs, check-temp-extend-reflect.mjs, 추후_개발_점검_연동_가이드.md |

## 2. 현재까지 개발된 것 (테스트 모드 — 일부)

테스트 모드는 **로컬 테스트 전용**이며, 운영 로직/데이터를 변경하지 않습니다.

| 항목 | 내용 |
|------|------|
| 상태 변수 | testModeEnabled, testModeOverrides (메모리) |
| override 병합 | mergeTestOverrides(base) |
| getWorkTime 테스트 경로 | testModeEnabled && overrides 있으면 API 우회, 병합 결과 반환 |
| IPC | pcoff:getTestModeState, pcoff:setTestModeEnabled, pcoff:setTestOverrides |
| 브로드캐스트 | enabled 변경 시 pcoff:test-mode-changed 전송 (setTestOverrides 변경 브로드캐스트는 미구현) |
| setTestOverrides 시 | lastWorkTimeData·lastWorkTimeFetchedAt 갱신 |

## 3. 남은 개발 사항 — 에이전트 단독 진행 가능

### 3.1 테스트 모드 (1단계 우선)

| # | 작업 | 담당 | 상세 |
|---|------|------|------|
| 1 | forceScreenType | Main | getWorkTime·isLockRequired·주기 잠금 검사·잠금창 초기 데이터 경로에 AUTO/BEFORE/OFF/EMPTY 강제 적용 |
| 2 | forceOperationMode | Main | 테스트 모드에서만 currentMode 강제 (AUTO/NORMAL/TEMP_EXTEND/EMERGENCY_USE/EMERGENCY_RELEASE) |
| 3 | 설정 저장/복원 | Main | test-mode-state.json 전용 저장·복원 (state.json과 분리) |
| 4 | 핫키 | Main | Ctrl+Shift+T / Cmd+Shift+T 등록·해제 |
| 5 | Preload 테스트 API | Preload | getTestModeState, setTestModeState(patch), onTestModeChanged 노출 |
| 6 | 테스트 모드 토글 UI | Renderer | 작동정보 상단 우측 토글, ON 시 Drawer 오픈 연동 |

**1단계 완료 기준**: 핫키/토글로 테스트 모드 ON/OFF, forceScreenType으로 시업/종업/이석 화면 즉시 재현, 재시작 후 설정 복원.

### 3.2 테스트 모드 (2·3단계)

| 단계 | 작업 | 상세 |
|------|------|------|
| 2단계 | Drawer UI | Test Mode Panel, 기본·시간/근태·정책 입력, applyTestPreset, 적용 즉시 반영 |
| 3단계 | 문구 override·로그·가이드 | before/off/leave 문구·리소스 override, TEST_MODE_* 로그, allowTestMode·트레이 노출 제어 |

## 4. 남은 개발 사항 — 서버/백엔드 선행 필요

에이전트는 호출부·Fallback·검증 스크립트까지 준비된 상태입니다. **서버(또는 DB) 구현 후** 연동·E2E만 진행하면 됩니다.

### 4.1 우선 마무리 (1→2→3)

| 순서 | 항목 | 담당 | 내용 | 에이전트 측 점검 |
|------|------|------|------|------------------|
| 1 | 이석 해제 비밀번호 | 서버 | POST /verifyLeaveSeatUnlock.do(또는 동일 API) 구현. PHP(leaveSeatUnlockVerifyUrl)만 써도 동작 가능. | 연동·E2E, `node scripts/run-integration-check-1-2-3.mjs` 또는 가이드 §1 |
| 2 | 잠금화면 문구 API | 서버(선택) | getLockScreenInfo.do, GET .../lock-policy. 미구현 시 config·lockScreenApiUrl Fallback | `node scripts/check-lock-screen-config.mjs` |
| 3 | 임시연장 서버 반영 | 서버/DB | callPcOffTempDelay 수신 후 JsonMapper·프로시저·DB 갱신 | 터미널·UNLOCK_TRIGGERED 로그 비교, `node scripts/check-temp-extend-reflect.mjs [logs경로]` |

**참고**: `docs/추후_개발_점검_연동_가이드.md` — 서버 구현 완료 조건·E2E 체크리스트·통합 실행 방법.
