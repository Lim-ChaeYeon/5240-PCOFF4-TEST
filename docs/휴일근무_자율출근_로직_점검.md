# 휴일근무·자율출근 관련 로직 점검 결과

요청하신 시나리오별로 **에이전트(클라이언트) 로직이 정상 작동 가능한지** 점검한 결과입니다.  
잠금/해제 기준은 `getPcOffWorkTime.do` 응답의 **pcOnYmdTime / pcOffYmdTime**과 현재 시각 비교이며, 휴일·자율출근 구분은 **서버가 내려주는 시간/플래그**에 의존합니다.

---

## 1. 휴일근무 신청-승인이 있을 경우

| 요구사항 | 반영 주체 | 에이전트 동작 | 정상 여부 |
|----------|-----------|----------------|-----------|
| 휴일근무 **From~To가 있을 경우** 반영 | **서버** | `getPcOffWorkTime`의 `pcOnYmdTime`·`pcOffYmdTime`을 그대로 사용 | ✅ 서버가 해당 구간을 내려주면 정상 |
| 휴일근무 **From~To가 없을 경우** 근태기준 휴일근무 설정 반영 | **서버** | 동일 — 클라이언트는 항상 응답의 `pcOnYmdTime`/`pcOffYmdTime`만 사용 | ✅ 서버가 근태기준 구간을 내려주면 정상 |

**로직 요약**

- 클라이언트는 **휴일근무 From~To**와 **근태기준 휴일근무**를 구분하지 않습니다.
- `/getPcOffWorkTime.do` 응답의 `pcOnYmdTime`(PC 사용 가능 시작), `pcOffYmdTime`(PC 사용 종료, 임시연장 반영)만으로 잠금 여부를 판단합니다.
- 따라서 “휴일근무 From~To 반영” / “없을 때 근태기준 반영” 모두 **서버에서 위 두 값으로 적절히 내려주면** 에이전트는 정상 작동합니다.

---

## 2. 휴일에 출근체크가 있을 경우 — 자율출근일 때

| 요구사항 | 에이전트 동작 | 정상 여부 |
|----------|----------------|-----------|
| 잠금화면에서 **PC-ON 누르면 화면 풀림** | PC-ON 시 `callCmmPcOnOffLogPrc(IN)` 후 `getPcOffWorkTime`으로 갱신. `pcOnYmdTime ≤ now < pcOffYmdTime`이면 잠금 해제 후 작동정보로 전환 | ✅ 서버가 사용가능 구간을 내려주면 정상 |
| **PC를 켤 때** 잠금화면 없이 사용 | 앱 기동 시 `checkLockAndShowLockWindow()` → `isLockRequired()` → `getPcOffWorkTime` 후 `now`가 `[pcOnYmdTime, pcOffYmdTime)` 안에 있으면 잠금 미표시 | ✅ 서버가 해당 시각을 사용가능 구간으로 내려주면 정상 |

**주의**

- 클라이언트는 **`freeTimeWorkTypeYn`(자율근무제 여부)** 을 **어디에서도 사용하지 않습니다** (타입/필드만 존재).
- “PC를 켤 때 잠금화면 없이”는 **서버가 자율출근일 때** `pcOnYmdTime`~`pcOffYmdTime`을 당일 사용가능 구간(또는 넓은 구간)으로 내려줄 때만 보장됩니다.
- 서버가 자율출근인데도 잠금 구간으로 내려주면, 에이전트는 그대로 잠금화면을 띄웁니다.  
  → 필요 시 서버에서 자율출근 휴일 출근 시 **사용가능 구간을 명확히** 내려주거나, 클라이언트에 `freeTimeWorkTypeYn === 'Y'` + `pcOnYn === 'Y'`일 때 기동 시 잠금 생략 로직을 추가하는 방안을 검토할 수 있습니다.

---

## 3. 휴일에 출근체크가 있을 경우 — 휴일근무 시업~종업이 있을 때

| 요구사항 | 에이전트 동작 | 정상 여부 |
|----------|----------------|-----------|
| 휴일 잠금화면에서 PC-ON → **시업 전(시업화면 조건)** 이면 **시업화면 표시** | PC-ON 요청 후 서버가 여전히 잠금(시업 전)이면 `stillLocked: true` 반환 → 토스트 “현재 PC-ON이 불가능합니다. 시업 시간에만 가능합니다.” 후 `refreshLockScreenFromWorkTime()`으로 최신 근태 조회 및 잠금화면 갱신 → `screenType === "before"` 이면 시업 전 문구·화면(시업화면) 표시 | ✅ 정상 |
| **사용가능 시간대**이면 **화면 풀림** | `now`가 `[pcOnYmdTime, pcOffYmdTime)` 안이면 `stillLocked` 없이 잠금 해제 → 작동정보로 전환 | ✅ 정상 |
| **PC 사용가능 시간대에 PC를 켜면** 잠금화면 없이 사용 | 기동 시 `isLockRequired()`가 `getPcOffWorkTime` 결과로 `pcOnYmdTime`~`pcOffYmdTime`과 `now` 비교. 사용가능 구간이면 `locked === false` → 잠금창 미표시 | ✅ 서버가 휴일근무 시업~종업 구간을 `pcOnYmdTime`/`pcOffYmdTime`으로 내려주면 정상 |

**관련 코드**

- **시업 전 PC-ON 시 시업화면 유지**:  
  `app/main/index.ts` — PC-ON(IN) 처리 후 `getPcOffWorkTime`으로 갱신, `pcOnT`/`pcOffT`와 `now` 비교해 잠금이면 `stillLocked: true` 반환.  
  `app/renderer/lock.js` — `result?.stillLocked`일 때 토스트 표시 후 `refreshLockScreenFromWorkTime()` 호출 → `applyLockScreenContent`/`applyButtonDisp`로 시업 전(before) 화면 표시.

## 4. 요약 표

| 구분 | 요구 동작 | 클라이전트 상태 | 전제 조건 |
|------|-----------|-----------------|-----------|
| 휴일근무 From~To 있음 | 해당 구간 반영 | ✅ 가능 | 서버가 해당 구간을 `pcOnYmdTime`/`pcOffYmdTime`으로 반환 |
| 휴일근무 From~To 없음 | 근태기준 휴일근무 반영 | ✅ 가능 | 서버가 근태기준 구간을 `pcOnYmdTime`/`pcOffYmdTime`으로 반환 |
| 휴일 출근 + 자율출근 | 잠금화면에서 PC-ON → 풀림 | ✅ 가능 | 서버가 사용가능 구간 반환 |
| 휴일 출근 + 자율출근 | PC 켤 때 잠금 없음 | ✅ 가능 | 서버가 기동 시각을 사용가능 구간으로 반환 (클라이언트는 `freeTimeWorkTypeYn` 미사용) |
| 휴일 출근 + 시업~종업 | 시업 전 PC-ON → 시업화면 표시 | ✅ 구현됨 | `stillLocked` + 잠금화면 갱신으로 시업 전 화면 유지 |
| 휴일 출근 + 시업~종업 | 사용가능 시간대 PC-ON → 풀림 | ✅ 가능 | 서버가 휴일근무 구간 반환 |
| 휴일 출근 + 시업~종업 | 사용가능 시간대에 PC 기동 → 잠금 없음 | ✅ 가능 | 서버가 휴일근무 구간 반환 |

**결론:**  
요청하신 휴일근무·자율출근·시업~종업 시나리오는 **서버가 `getPcOffWorkTime.do`에서 휴일/자율/시업~종업에 맞는 `pcOnYmdTime`·`pcOffYmdTime`(및 필요 시 `screenType`)을 내려주는 경우** 현재 에이전트 로직으로 **정상 작동 가능**합니다.  
자율출근 “PC 켤 때 잠금 없음”을 서버 응답과 무관하게 보장하려면, 클라이언트에 `freeTimeWorkTypeYn === 'Y'` + `pcOnYn === 'Y'`일 때 기동 시 잠금 생략 로직을 추가하는 옵션을 고려할 수 있습니다.
